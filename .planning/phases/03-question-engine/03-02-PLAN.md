## Question schema (from database.ts)

Each Question row has:
  - track: string (DB stores Track enum values)
  - language: Language ('en' | 'ar')
  - question_no: number (1–10)
  - question_text: string
  - answer_a_text: string | null    — null for image-answer questions
  - answer_a_image_url: string | null — null for text-answer questions
  - answer_b_text: string | null
  - answer_b_image_url: string | null
  - answer_c_text: string | null
  - answer_c_image_url: string | null
  - correct_answer: CorrectAnswer ('A' | 'B' | 'C')

A question has EITHER text OR image_url populated per answer slot — not both.
Four questions (A&D Q6, Legal Q6, Marketing Q9, Operations Q4) use image answers for EN;
their AR counterparts use text answers.

## Error handling pattern (from session.ts)

Throw on failure (missing questions = broken game, caller must handle).
Return empty array only if the query succeeds but returns no rows (not an error state,
just means questions aren't seeded yet — Phase 4/5 can show a loading/empty state).

    ```typescript
    import { supabase } from '@/lib/supabase'
    import type { Question, Track, Language } from '@/types/database'

    export async function getQuestionsForTrack(
      track: Track,
      language: Language
    ): Promise<Question[]> {
      const { data, error } = await supabase
        .from('questions')
        .select('*')
        .eq('track', track)
        .eq('language', language)
        .order('question_no', { ascending: true })

      if (error) {
        throw new Error(`Failed to load questions for ${track} (${language}): ${error.message}`)
      }

      return (data ?? []) as Question[]
    }
    ```

    No other exports needed. Callers (Phase 4/5) use this to load all 10 questions for the
    active session's track + language when entering question_active state.

    The function is intentionally simple: one query, typed return, throw on error.
    Do NOT add caching, retry logic, or prefetching — those belong in the consumer hooks (Phase 4/5).
